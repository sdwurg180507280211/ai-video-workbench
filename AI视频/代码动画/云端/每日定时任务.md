2. 会话启动时打印过一行「[session] 视频制作环境：…」。ffmpeg、Chrome、Python 库、mgaudio、视频技能都要「有」。如果没看到这行，就自己运行 `bash AI视频/代码动画/云端/session_start.sh`。
3. 环境变量 IMAGE_API_KEY、DOUBAO_SPEECH_API_KEY、DEEPSEEK_API_KEY 都要存在。只报告「存在 / 不存在」，绝不打印、回显或写进文件，也不要 set -x。

### 1. 取题
- 读 AI视频/代码动画/选题清单.md。有「在做」的，先接着做完那一支：读它目录里的 交接.md，从断点继续。否则取第一条「待做」。
- 定一个 2～4 个字的中文短名做目录名：AI视频/代码动画/<短名>/。
- 马上把这一条改成「在做」，填上目录，提交并推送。这样中途断了，明天的任务能接着做。
- 「待做」少于 3 条时，按清单开头的要求补 3 条新题。

### 2. 旁白稿（剧本.md）
- 按制作流程第 2 步写：定位、这一支要比前几支好在哪（对照教训来写）、旁白表（时间、段落、画面、旁白）、事实边界。
- 每支片讲清一个机制，用一个日常类比撑住画面。片长按"讲没讲透"定：一句里不要塞两三个概念，画面上出现的东西旁白要交代，抽象概念要讲清"为什么"。新概念至少停 7 秒。
- 事实要核对：用 WebSearch / WebFetch 查权威来源（论文、官方文档）。示意数字在画面上标「示例」。

### 3. 审稿（代替用户审批）
- 运行 `python3 ~/ideaProjects/my-skills/skills/seedance-short-drama/scripts/review_script.py 剧本.md --context "纯代码逐帧渲染的贴纸科普短片，童声旁白，没有视频模型的单段时长限制；给对 AI 好奇的普通人看" --out 审稿/审稿_DeepSeek_第N轮.md`，复查时加 `--prev`。
- 逐条判断：采纳、改着采纳或驳回，每条都写理由，记进剧本末尾的「审稿」一节。事实类意见要查证后再决定。版权、合规类意见默认不采纳。
- 一直改到两路都是"必须改：无"，最多 4 轮。4 轮后还有事实类的必须改：这支片改成「暂停」，写清卡在哪，发通知，然后结束本轮（不要换题硬做）。
- 定稿后把 voice/旁白.txt 写成每行一句。

### 4. 建工程
- 以最近完成的一支（目前是 AI视频/代码动画/雪花变画/）为模板：复制 harness/、package.json、film/build_cues.py、film/audio.py、cover_gw.py、tools/ 的结构，然后改。不要用 Mac 的 ~/Downloads 路径。
- `assets/fonts` 做成软链接 `../../共用/fonts`。贴纸从 AI视频/共用/小团子AI素材/动作/透明/ 复制到 assets/xiaotuanzi/。
- 运行 `bash AI视频/代码动画/云端/session_start.sh`，给新目录建 lib、.venv、node_modules。
- 按剧本列出小团子需要的动作，和素材清单逐个对照。缺的用生图网关出（参考 tools/gen_stickers.py；参考图加纯色浅蓝底，用素材库的 抠图.py 抠图）。新贴纸收进 AI视频/共用/小团子AI素材/ 并登记到素材清单.md。网关一直出不来，就用最接近的现成动作加代码画的道具顶上，并在交接.md 里记下来。

### 5. 配音、节拍、画面、配乐
- 配音：`python3 ~/ideaProjects/my-skills/skills/opus-code-video/scripts/doubao_tts.py lines ICL_uranus_zh_female_ruanmengtuanzi_tob <工程> --rate -4`。记下总字数，写进通知。
- 节拍：film/build_cues.py 按每句的说话时长排段，画面事件钉在旁白的词上；再运行 retime.py。画面和配乐只读 film/cues.json。
- 画面：film/index.html。先出 8～12 张关键帧（`node harness/render.mjs film --stills …`），拼成总览图，用 Read 逐张看：构图、压线、出安全区、字够不够大、类比画得像不像（教训里的车门、空镜、拉远字太小……）。至少改一轮，再出一轮关键帧确认。
- 配乐：`.venv/bin/python film/audio.py`，再运行 `.venv/bin/python ~/ideaProjects/my-skills/skills/opus-code-video/scripts/mix_voice.py .`。hit_alignment 要在 ±3 帧内。

### 6. 渲染、质检
- 整片渲染放后台：`nohup node harness/render.mjs film --mb 8 --workers 4 > film/out/render.log 2>&1 &`，每隔几分钟看一次 `tail -1 film/out/render.log`，等它结束。
- 运行 `qc.py film/out/video.mp4 --duration <秒>`，每 2 秒抽一帧拼成总览图，用 Read 看节奏和空镜。发现明显问题就修，再渲染一次。整片最多渲染 2 次。
- 自评（风格、创意、动作、版式、质感、声音、技术，各 1–10 分），写出最弱的三点。

### 7. 封面、交付、收尾

- 成片复制成 <短名>_v1.mp4，运行 `bash AI视频/代码动画/云端/deliver.sh AI视频/代码动画/<短名> v1`，传到草稿 Release。
- 写这支片的 作品.json（状态「已完成」）和 交接.md（现在到哪、怎么跑、自评最弱三点、发布用的标题和简介）。
- 选题清单里把这一条改成「已做」，填上目录。AI视频/README.md 的作品表加一行。
- 这次学到、下次该照做的教训，追加到 AI视频/代码动画/教训_待并入技能.md（带日期和片名）。云端改不了 my-skills 仓库，用户会定期并进技能。
- 提交并推送到 main：代码、配音 mp3、贴纸、封面、文档都要提交；mp4、wav、film/out/ 不提交（.gitignore 已经忽略）。推送被拒就先 `git pull --rebase` 再推。
